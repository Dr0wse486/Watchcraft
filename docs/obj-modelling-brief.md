# 角色

你是一名 Minecraft 模组 3D 资产工程师，熟悉原版实体模型的视觉语言，也熟悉 Wavefront OBJ 格式。
请为一架**四轴侦查无人机**建出可直接被 NeoForge 1.21.1 的 OBJ 加载器读取的模型。

# 交付物

**一个纯标准库的 Python 脚本** `generate_drone_mesh.py`（只 import `math` / `json` / `os`）。
运行后生成 5 个文件：

| 文件 | 内容 |
|---|---|
| `drone.obj` | 机体全部不发光部件 |
| `drone.mtl` | 机体材质库 |
| `drone_glow.obj` | 只含发光部件（镜头 / 尾灯） |
| `drone_glow.mtl` | 发光件材质库 |
| `drone_manifest.json` | UV 布局清单 + 每个部件的旋转中心（见 §6） |

**为什么交付脚本而不是直接手写 OBJ 文本**：整机 400 个面手写必出错（顶点索引、UV 分配、
4 条机臂的对称性都容易写歪），而且 OBJ 文本太长会被截断。脚本用循环和工具函数生成，
可以保证索引正确、4 条机臂严格对称、UV 自动分配不重叠。

# 1. 坐标系与单位（写错整个模型就废了）

- **1.0 = 1 个 Minecraft 方块。不是 16。** NeoForge 的 OBJ 加载器不做 `/16` 缩放。
- **Y 轴向上。机头朝 -Z**（前方 / 北）。+X 是机体**右侧**。
- 原点 `(0,0,0)` 在**机体的几何中心**（不是脚底、不是某个角）。
- 下文用 **U 表示 1/16 格 = 0.0625**，所有尺寸都用 U 表达。

## 1.1 整机硬包围盒（不得超出）

| 轴 | 范围 | 说明 |
|---|---|---|
| X | `[-6U, +6U]` = `[-0.375, +0.375]` | 含桨叶，翼展 0.75 格 |
| Y | `[-3U, +3U]` = `[-0.1875, +0.1875]` | 上到天线顶，下到起落架底 |
| Z | `[-5U, +2.5U]` = `[-0.3125, +0.15625]` | 机头长、机尾短 |

> 宿主实体的碰撞箱是 **0.8 × 0.45 格**，渲染时原点会被抬到碰撞箱中心。必须留出余量。

## 1.2 顶点网格吸附（**最重要的风格约束**）

**所有顶点坐标必须是 `0.03125`（= 0.5U）的整数倍。**

这是 Minecraft 视觉语言的根基：几何棱线落在整数像素网格上，模型才"看起来是方块拼的"；
一旦出现任意浮点坐标，斜边就会产生亚像素抖动（纹理闪烁），并且和周围的原版实体割裂。

```python
U = 1.0 / 16.0          # 0.0625
H = 0.03125             # 半格，最小步进

def snap(v):
    """把坐标吸附到 1/32 格网格。每个顶点写出前都要过这个函数。"""
    return round(v / H) * H
```

允许的最小厚度就是 `H`（0.03125 格）。

# 2. 风格：Minecraft 原版感优先，无人机主体其次

核心要求：它必须一眼看起来是"原版 Minecraft 里会出现的东西"，
而不是一个从 Blender 导出的精细模型。

| 规则 | 说明 |
|---|---|
| **面片化（faceted）** | 每个面一个法线（flat normal）。**不写 `s` 行**，或统一写 `s off`。禁止平滑着色 |
| **低多边形** | 整机 ≤ 400 个面（§4）。细节靠贴图，不靠几何 |
| **斜切而非圆角** | 收边用 **chamfer（斜切面）**，不用 fillet（圆弧倒角）。机头是 2–3 段斜切面拼出的楔形 |
| **面以四边形为主** | 允许三角形，禁止五边形及以上。四边形是 Minecraft 模型的原生单位 |
| **厚度有下限** | 最薄 0.5U（0.03125）。不要做纸片 |
| **严格镜像对称** | 整机关于 X=0 平面镜像对称 |

**唯一例外**：圆柱 / 棱柱类部件（电机、桨毂、天线顶端小球）允许顶点不落在网格上，
但必须段数少（6–8 边），且外接圆直径是 U 的整数倍。

**造型方向**：工业四轴无人机的骨架，轮廓方正厚重——
机身是扁长棱台不是胶囊；机头是楔形不是流线锥；机臂是方杆（截面 `1U × 0.5U`）不是圆管；
电机是八棱柱；桨叶是两叶交叉的薄板（每叶长 `2U`、宽 `1U`、厚 `0.5U`）；
起落架是两根方杆滑橇加 2 根斜撑。

|---|---|---|---|---|
| `gimbal_lens` | 镜头（朝 -Z 的发光圆窗） | `X ±1U`，`Y [-2U, -1U]`，`Z [-4U, -3U]` | `(0, -1U, -3U)` | 12 |

## 3.1 机臂与电机的精确位置（必须严格对称）

| i | 方位 | 机臂锚点 | 电机轴心 |
|---|---|---|---|
| 0 | 右前 | `(+2U, 0, -2U)` | `(+4U, 0, -4U)` |
| 1 | 右后 | `(+2U, 0, +2U)` | `(+4U, 0, +4U)` |
| 2 | 左后 | `(-2U, 0, +2U)` | `(-4U, 0, +4U)` |
| 3 | 左前 | `(-2U, 0, -2U)` | `(-4U, 0, -4U)` |

- 机臂是方杆，沿锚点→轴心方向伸出，水平投影长度 `2U√2`。
- **用循环生成 4 条臂 / 4 个电机 / 4 个桨叶**，通过绕 Y 轴 90° 旋转派生，保证严格对称。
  不要手写 4 份。
- 桨叶最大伸展 `4U + 2U = 6U = 0.375` 格 → 翼展 0.75 格，在 §1.1 的硬包围盒内。

# 5. UV：不要自己发明，用确定性装箱器

- 全部非发光件共用**一张贴图**；发光件用**另一张**。
- **UV 用像素坐标归一化**：`u = x / W`，`v = y / H`（v 向下）。OBJ 的 `vt` 保留 6 位小数。
- 装箱规则（严格按这个来，贴图生成脚本依赖它）：
  1. 按 §3 表格从上到下的顺序依次处理部件；
  2. 每个面按"自然尺寸"取矩形：水平面用 `(宽 × 深)`，竖直面用 `(宽 × 高)` 或 `(深 × 高)`；
     单位是贴图像素，比例 **`1U` = 8 像素**（机身 `4U` 宽 = 32 像素）；
  3. 矩形之间留 **1 像素**间隙，整张图四周留 **2 像素**边距；
  4. 用 **shelf packing（货架装箱）**：从左到右铺，铺不下就换行，行高 = 本行最高矩形；
  5. 按上面的比例估算，整机 UV 面积约 2 万 px²，**128×128 装不下**，
     所以直接按 **`256×256`** 起算；发光件少，用 `128×128` 即可。
     最终尺寸写进 manifest 的 `sheet` / `glow_sheet`。

# 6. `drone_manifest.json`

字段名逐字符一致：

```json
{
  "unit": 0.0625,
  "sheet": [256, 256],
  "glow_sheet": [128, 128],
  "parts": [
    {
      "group": "frame",
      "mesh": "drone",
      "pivot": [0.0, 0.0, 0.0],
      "faces": 58,
      "bbox": [[-0.125, -0.0625, -0.3125], [0.125, 0.0625, 0.125]]
    }
  ],
  "faces": [
    {
      "group": "frame",
      "name": "top",
      "rect": [2, 2, 32, 20],
      "uv": [[0.0078125, 0.0078125], [0.1328125, 0.0078125],
             [0.1328125, 0.0859375], [0.0078125, 0.0859375]],
      "colour": "HULL_DARK"
    }
  ]
}
```

- `parts[].pivot`：该部件的旋转中心，**世界坐标（格）**。渲染代码围绕它做旋转。
- `parts[].mesh`：`"drone"` 或 `"drone_glow"`。
- `faces[].rect`：`[x, y, w, h]`，贴图像素坐标（左上角为原点）。
- `faces[].uv`：4 个角归一化后的 UV，顺序与 OBJ `f` 行的顶点顺序一致。
- `faces[].colour`：建议主色名（取自 §9 调色板），给贴图脚本一个起点。

# 7. 材质文件（内容固定，照抄）

`drone.mtl`：

```
newmtl drone_mat
Ka 0.000 0.000 0.000
Kd 1.000 1.000 1.000
Ks 0.000 0.000 0.000
d 1.0
illum 1
map_Kd #texture0
```

`drone_glow.mtl`：同上，但 `newmtl drone_glow_mat`。

三条不可改动：
- `Kd` 必须纯白——所有颜色由贴图决定，材质不参与调色；
- `Ka` 必须全 0——自发光由渲染代码控制，`Ka` 非 0 会让模型在暗处变灰；
- `map_Kd` 必须是 `#texture0` 这个**变量名**，不是文件路径。

# 8. OBJ 文件格式硬要求

```
# Recon Drone — 1.0 = 1 Minecraft block, Y up, nose towards -Z
mtllib drone.mtl

v  -0.125 0.0625 -0.3125
vt 0.0078125 0.0078125
vn  0.0 1.0 0.0

g frame
usemtl drone_mat
f 1/1/1 2/2/1 3/3/1 4/4/1
```

- 索引**从 1 开始，全部正数，禁止负索引**。
- 顶点池 `v` / `vt` / `vn` 可以全局共用，但**每个 `g` 组必须重新声明 `usemtl`**。
- **不要**出现：`vc` 行、`s` 行、`o` 行、`usemap` 行、五边形以上的 `f` 行。
- 面的顶点顺序按**从外部看的逆时针**排列，保证法线朝外。
- 每个 `g` 组用注释标出它的 pivot，例如 `# pivot: 0.125 0.0 -0.125`。
